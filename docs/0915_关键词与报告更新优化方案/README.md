# 认知雷达关键词与报告更新优化方案

日期：2026-09-15

本目录针对公司现有版本的两个问题给出可落地方案：

1. 如何生成领导愿意使用的拆分关键词和子问题。
2. 如何利用一轮问题、回答、Web Search 查询及信源，更新总体认知报告和子问题报告。

## 核心结论

“关键词”应分成两个产物：

- **模块短标题**：给领导看，2—6 个字，表达一个管理问题，如“存储需求”“投入窗口”。
- **检索查询词**：给 Web Search 用，可以较长并包含对象、时间、指标、反向词和来源限定，如“2026 深度学习训练 内存带宽 DRAM 需求 一手数据”。

模块短标题不能直接由 Topic 关键词抽取产生。更稳妥的顺序是：识别领导要做的判断，整理材料中的议题，形成完整子问题，最后压缩成短标题。

报告更新采用“认知变更判定与路由”：既检查回答中的候选认识，也检查本轮信源是否直接反驳范围内的旧观点。结果可以是新增、补强、限定、修正、退出当前版本、保留冲突或完全不改。变更优先作用于最具体的子问题报告；只有当它改变总体结论、资源优先级、风险暴露、行动时点或关键观察信号时，才联动总体报告。

## 当前基线与建议新增

| 能力 | 当前仓库基线 | 本方案建议新增 |
| --- | --- | --- |
| 拆分 | 文献排序、证据提取、候选模块、2—6 字 `themes` | Query 计划、议题卡、完整子问题与短标题分步生成、领导词汇反馈 |
| 更新 | 单份 Markdown 的局部修改、证据校验、版本与确认 | 子问题路由、总体联动门槛、依赖图、跨文件更新批次 |

本目录是优化设计稿，不表示建议新增部分已经写入运行代码。

## 推荐整体流程

```text
Topic + 领导问题
    ↓
识别话题类型与决策任务
    ↓
生成多组 Web Search 查询并检索
    ↓
文献去重、排序、提取证据议题
    ↓
生成完整子问题并收敛结构
    ↓
压缩成 2—6 字模块标题
    ↓
生成总体报告与子问题报告
    ↓
对话问题 + 被采纳回答 + 查询记录 + 信源
    ↓
判定认知变更、核实新旧证据、路由目标报告
    ↓
生成完整候选报告，审查后确认提交
```
